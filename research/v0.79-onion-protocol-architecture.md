# v0.79 — Onion / Protocol Architecture Reconstruction

## Result

**Decision: PROTOCOL_LAYER_CHANNEL_CONFIRMED_AS_HISTORICAL_CICADA_METHOD**

The Tor/.onion layer should be treated as a legitimate puzzle-bearing channel, not merely as anonymity infrastructure.

## Strong evidence

### 2013 first onion
The preserved page `emiwp4muu2ktwknf.html` explicitly says:

> Web browsers are useless here.

This is direct evidence that solvers were expected to look beyond ordinary HTTP page content.

### 2013 second onion
A signed clue said:

> Sometimes one must "knock on the sky and listen to the sound."

The intended mechanism was ICMP/ping. Echo replies carried appended hex data. Concatenating and decoding that stream produced a gzip archive containing a PGP-signed message with the next onion address.

This establishes a concrete historical pattern:

1. visible clue text
2. protocol behavior
3. hidden binary payload
4. container decoding
5. PGP authentication
6. next-stage onion address

### Liber Primus onion7
The preserved LP index source contains:

- `<title>133</title>`
- `<div id="331">`
- 58 images, `0.jpg` through `57.jpg`

This places deliberate numeric source-layer metadata immediately around the LP corpus.

## Architectural implication for LP2

A missing LP2 state/key/selector may plausibly exist outside the rune ciphertext itself. Historically demonstrated Cicada channels include:

- HTML/source metadata
- application state / cookies
- ports and protocol behavior
- ICMP/TCP payloads
- binary containers
- PGP-authenticated messages
- onion addresses / stage transitions

This makes unrestricted rune-only key search less attractive. Protocol-origin values should be used only as predeclared selectors, phases, reset schedules, state labels, or initialization parameters.

## Rules for next attack

1. Promote only values preserved in authenticated/original artifacts or recurring independently across stages.
2. Do not treat every port or server artifact as intentional clue material without recurrence.
3. Use protocol-origin values as selectors/state controls, not freely searched additive keys.
4. Require held-out validation on an independent LP2 section.
5. Keep protocol-origin selectors separate from red-event selectors until a model is frozen.
